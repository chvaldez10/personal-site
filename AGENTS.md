# Project guidance for coding agents

## Project map

- The application is in `chvaldez10/`; run app commands from that directory. The repository root contains project documentation.
- The app uses Next.js 16 App Router, React 19, TypeScript 7, Tailwind CSS 4, shadcn/Radix components, and Supabase. Use `pnpm` (see `packageManager` in `chvaldez10/package.json`), not another package manager.
- Route files and layouts live in `src/app/`. Reusable UI lives in `src/components/`; homepage sections are in `src/components/core/hero/`. Static project and navigation content lives in `src/constants/`; shared types and helpers live in `src/types/` and `src/lib/`. Supabase clients live in `src/utils/supabase/`.
- Also read `chvaldez10/AGENTS.md` before changing app code. Its Next.js rules are generated by Next and should remain intact. For the Next API you are changing, consult the installed guide under `chvaldez10/node_modules/next/dist/docs/` as that file directs.

## Making changes

- Make the smallest coherent change that solves the request. Match nearby naming, file organization, import style, and formatting; avoid unrelated rewrites or new dependencies without a clear need.
- Keep pages and layouts focused on composition and routing. Put reusable presentation in components, shared content in constants, and server data access in server-side modules. Use the `@/` alias for imports from `src/`.
- Keep components as Server Components unless they need browser state, event handlers, or browser APIs. Add `"use client"` only at the smallest necessary boundary; do not import server-only code into client components.
- Use the existing Supabase client appropriate to the execution context (`src/utils/supabase/server.ts` or `client.ts`). Treat authentication and authorization as server-side concerns. Validate form input and handle query errors before using data; do not expose secrets or add service-role credentials to client code.
- Reuse existing UI primitives and design tokens before adding new styles. Keep layouts responsive, preserve keyboard access and visible focus states, and provide useful text alternatives for images and controls. Follow `src/components/core/hero/README.md` when working in that section.
- Prefer explicit TypeScript types for external data and component contracts. Avoid `any`, non-null assertions on uncertain values, and silent error handling. Do not change generated files or the lockfile except when the task requires it.

## Verification

- From `chvaldez10/`, run `pnpm typecheck` and `pnpm lint` after code changes. Run `pnpm build` when changing routes, server behavior, configuration, dependencies, or other build-sensitive code. Check the affected UI in a browser when visual behavior changes, if a browser is available.
- `pnpm lint` runs Oxlint. The checked-in ESLint config is currently inactive because of the TypeScript 7 compatibility issue documented in `docs/package-upgrade/eslint-typescript-7-conflict.md`; do not substitute `eslint .` for the project lint command.
- Add or update focused tests only when they verify meaningful behavior. There is no configured test script yet, so do not claim tests ran unless you add and execute a real test command.
- Report what changed, which checks ran, and any unresolved issue. Keep unrelated user changes intact.
